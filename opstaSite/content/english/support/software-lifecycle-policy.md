## Software Lifecycle Policy

This document outlines Opsta's software lifecycle policy for our DevSecOps and Platform Engineering solutions, including support timelines, maintenance procedures, and end-of-life processes.

### Policy Overview

Opsta is committed to providing reliable, secure, and well-maintained software solutions throughout their entire lifecycle. This policy ensures transparency and predictability for our customers regarding software support and maintenance.

### Lifecycle Phases

#### 1. Active Development Phase

-   **Duration**: Varies by product
-   **Support Level**: Full feature development and bug fixes
-   **Security Updates**: Immediate security patches
-   **Documentation**: Complete and up-to-date documentation
-   **Training**: Available training and certification programs

#### 2. Maintenance Phase

-   **Duration**: Minimum 2 years after active development
-   **Support Level**: Critical bug fixes and security updates only
-   **Security Updates**: Regular security patches within 30 days
-   **Documentation**: Maintained but no new feature documentation
-   **Training**: Limited to existing materials

#### 3. Extended Support Phase

-   **Duration**: Additional 1 year (available for enterprise customers)
-   **Support Level**: Security updates and critical fixes only
-   **Security Updates**: Security patches within 60 days
-   **Documentation**: As-is basis
-   **Training**: Not available for new features

#### 4. End-of-Life (EOL) Phase

-   **Support Level**: No further updates or support
-   **Migration**: Migration guidance and tools provided
-   **Timeline**: 6-month notice before EOL

### Product Categories

#### Opstella Platform

-   **Current Status**: Active Development
-   **Support Timeline**: 5+ years from initial release
-   **Update Frequency**: Monthly feature releases, weekly security updates
-   **LTS Versions**: Available with 3-year support guarantee

#### Open Source Tools and Integrations

-   **Support Model**: Community-driven with enterprise support options
-   **Update Frequency**: Follows upstream project schedules
-   **Security**: Immediate patches for critical vulnerabilities

#### Custom Solutions

-   **Support Timeline**: Defined in individual service agreements
-   **Maintenance**: Based on customer requirements and contracts
-   **Updates**: Scheduled maintenance windows

### Support Commitments

#### Security Updates

-   **Critical Vulnerabilities**: Patches within 24-48 hours
-   **High Severity**: Patches within 7 days
-   **Medium/Low Severity**: Included in regular update cycles

#### Bug Fixes

-   **Critical Issues**: Emergency fixes within 24 hours
-   **High Priority**: Fixes within 5 business days
-   **Standard Issues**: Included in next scheduled release

#### Compatibility

-   **Backward Compatibility**: Maintained within major versions
-   **API Changes**: 6-month deprecation notice for breaking changes
-   **Migration Tools**: Provided for major version upgrades

### End-of-Life Process

#### Notification Timeline

1. **Initial Notice**: 12 months before EOL
2. **Reminder Notice**: 6 months before EOL
3. **Final Notice**: 30 days before EOL
4. **EOL Date**: Support officially ends

#### Migration Support

-   Migration documentation and best practices
-   Automated migration tools where possible
-   Professional services for complex migrations
-   Extended support options for enterprise customers

### Customer Responsibilities

#### Staying Current

-   Regular system updates and patches
-   Monitoring security advisories
-   Planning for version upgrades
-   Testing in non-production environments

#### Communication

-   Subscribing to security notifications
-   Reporting security vulnerabilities responsibly
-   Providing feedback on lifecycle changes
